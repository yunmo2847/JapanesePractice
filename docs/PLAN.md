## 0. 한 줄 요약

**소리를 내지 않고도 "일본어로 바로 생각해서 바로 대답하는 힘"을 기르는 21일 프리토킹 훈련 웹앱.**

## 1. 목표 정의

### 1.1 단일 목표

> **프리토킹 실력 향상** — 준비되지 않은 주제에 대해, 일본어로, 멈추지 않고, 상대와 주고받으며 말할 수 있다.

특정 장소·상황 맞춤 표현 암기는 목표가 아니다. 모든 기능은 "프리토킹을 더 길게, 덜 막히게, 더 자연스럽게 만드는가?"로만 판단한다.

### 1.2 왜 소리 없이도 프리토킹이 늘 수 있나

프리토킹 실력은 **① 머릿속에서 문장을 만드는 속도**와 **② 입으로 소리 내는 능력**으로 나뉜다.
초급자가 프리토킹에서 막히는 원인은 대부분 ①이다 ("뭐라고 해야 하지?").
①은 타이핑·조립·속으로 말하기로 충분히 훈련할 수 있으므로, **이 서비스는 ①에 집중**하고 ②는 가능할 때만 보충한다.

| 구분 | 무음 환경에서 훈련 가능? | 이 서비스의 방법 |
|---|---|---|
| 문장 즉시 만들기 (인출) | ✅ | 시간 제한 타이핑, 블록 조립 |
| 문장 잇기·답 늘리기 | ✅ | 이어 쓰기 드릴, 답변 확장 공식 |
| 막혔을 때 바꿔 말하기 | ✅ | 금지어 챌린지, 생존 표현 |
| 주고받기 (듣고 바로 반응) | ✅ (이어폰) | 채팅형 대화, 빠른 반응 타이머 |
| 발음·입 근육 | ⚠️ 부분적 | 무성 쉐도잉(입모양만), 선택형 음성 모드 |

> **한계를 솔직히 명시**: 타이핑은 실제 말하기와 같지 않다. 발음과 "입에서 술술 나오는 감각"은 무음 훈련만으로 완성되지 않는다. 그래서 7일마다 **선택형 음성 체크인**(F9)을 두고, 할 수 없는 날은 건너뛰어도 커리큘럼이 진행되게 한다.

### 1.3 프리토킹 5가지 능력

| # | 능력 | 막히는 모습 | 무음 훈련 방법 |
|---|---|---|---|
| ① | **즉시 인출** | 아는 말인데 바로 안 나옴 | 한→일 10초 타이핑 카드 |
| ② | **문장 잇기** | 한 문장 쓰고 끝 | 접속 표현으로 이어 쓰기 |
| ③ | **답 늘리기** | 「はい、好きです。」로 끝 | 답 → 이유 → 예시 → 되묻기 공식 |
| ④ | **막혔을 때 버티기** | 단어 모르면 멈춤 | 금지어 챌린지(그 단어 없이 설명), 생존 표현 |
| ⑤ | **주고받기** | 답만 하고 대화가 끊김 | 채팅형 대화, 되묻기·맞장구 필수 미션 |

### 1.4 사용자 조건

| 항목 | 내용 |
|---|---|
| 사용자 | 나 1명 |
| 시작 실력 | 히라가나·가타카나 읽음, 문장은 거의 못 만듦 |
| 기간 | 21일 프로그램 (이후 자유 연습 모드로 계속 사용) |
| 하루 학습 시간 | 30~60분 |
| **학습 환경** | **소리 내어 말할 수 없음. 이어폰으로 듣기는 가능 (확정)** |
| **주 사용 기기** | **갤럭시 탭 (안드로이드)** (보조: 휴대폰·PC) |
| 기준 브라우저 | **크롬(안드로이드)** 1순위, 삼성 인터넷 2순위 |
| 출력 방식 | 기본: 타이핑(태블릿 화면 키보드) / 복습 카드: 블록 조립 / 보조: 속으로 말하기 / 선택: 음성 녹음 |

### 1.5 설계 원칙

1. **모든 기능은 무음으로 끝까지 진행 가능해야 한다.** 소리 내기가 필요한 기능은 전부 "선택"이며 건너뛰어도 진도에 지장 없다.
2. **시간 제한이 말하기를 대신한다.** 실제 대화처럼 생각할 시간을 제한해 "쓰기"가 "작문"이 아닌 "말하기 연습"이 되게 한다.
3. **매일 반드시 프리토킹(자유 대답)으로 끝난다.**
4. **내가 만든 문장은 반드시 귀로 다시 듣는다.** 타이핑한 문장을 TTS로 재생해 "소리로서의 내 문장"에 익숙해진다.
5. **빨리 만들고 바로 쓴다.** MVP는 2일 안에 Day 1을 할 수 있는 상태로 배포.

## 4. 기능 명세 (Feature Spec)

**P0** = MVP(2일 내), **P1** = 1주차 중, **P2** = 여유 있으면.

### F0. 일본어 입력 도우미 (모든 타이핑 기능의 기반) — P0

기기마다 일본어 키보드 설치·사용법이 달라 진입 장벽이 되므로, 앱 안에서 해결한다.

- [ ] **로마자 → 가나 자동 변환 입력창**: 일본어 키보드 설치 없이 `tabemasu` → `たべます` 실시간 변환 (라이브러리: `wanakana`)
- [ ] 기기의 일본어 키보드(IME)를 쓰는 경우에도 정상 입력됨 (변환 기능 끄기 옵션)
- [ ] 채점은 **가나 기준**: 한자로 써도, 가나로 써도 같은 문장으로 인정 (정답 데이터에 가나 표기 보관)
- [ ] 문장부호·띄어쓰기·장음 표기(ー/う) 차이는 채점에서 무시
- [ ] 모바일에서 입력창 포커스 시 화면이 키보드에 가려지지 않음 (제출 버튼이 키보드 위에 보임)
- [ ] **삼성 키보드 대응**: 입력창에 `autocomplete="off"` `autocorrect="off"` `autocapitalize="off"` `spellcheck="false"` 지정 → 자동 대문자·자동 수정·단어 추천이 로마자 입력을 망가뜨리지 않는다
- [ ] 안드로이드 키보드의 조합 입력(composition) 중에는 가나 변환을 보류하고 `compositionend` 이후 변환 → 글자가 두 번 입력되거나 커서가 튀지 않는다
- [ ] 삼성 키보드·Gboard 둘 다에서 `tabemasu` → `たべます`, `kkoi` → `っこい`, `nn` → `ん` 변환이 정상 동작
- [ ] (선택) 삼성 키보드에 일본어 자판을 추가해 쓰는 경우도 정상 입력 — 설정 화면에 추가 방법 안내: `설정 > 일반 > 삼성 키보드 설정 > 언어 및 키보드 형식 > 입력 언어 관리 > 日本語`

### F1. 프리토킹 채팅 (핵심 기능) — P0

실제 대화처럼 질문을 듣고 시간 안에 채팅으로 대답하는 화면.

- [ ] 상대(가상 친구)의 질문이 채팅 말풍선 + TTS로 나온다 (이어폰). 소리 끄기 모드에서는 텍스트만
- [ ] 목표 시간 30초 / 1분 / 2분 (주차별 기본값), 상단에 남은 시간 바
- [ ] 한 문장 입력 후 Enter → 내 말풍선으로 올라가고, 바로 다음 문장 입력 가능 (여러 문장 연속)
- [ ] **반응 타이머**: 질문 후 10초 동안 입력이 없으면 생존 표현 힌트가 살짝 표시됨 (예: `えっと…` `そうですね…`)
- [ ] "힌트 보기"(선택): 패턴 3개·단어 5개·접속 표현. 기본은 숨김
- [ ] 시간 종료 시 입력 잠금 → **자동 리포트** 표시:
  - 문장 수, 글자 수, 첫 반응까지 걸린 시간
  - 사용한 접속 표현 (하이라이트 + 개수)
  - 되묻기 포함 여부
  - 오늘 패턴 사용 여부
- [ ] **모범 답안** 공개: 3~8문장 + 한국어 해석 + TTS + 접속 표현 하이라이트. 내 답변과 좌우(PC/태블릿)·상하(폰) 비교
- [ ] **내 문장 듣기**: 내가 쓴 문장 전체를 TTS로 재생
- [ ] "다시 대답하기": 모범 답안 본 뒤 2회차. 1·2회차 리포트 비교
- [ ] "말하고 싶었는데 못 한 말" 메모(한국어) → 개인 카드 후보 목록에 추가
- [ ] 문법 정답/오답 자동 채점은 하지 않는다 (자유 대답이므로). 대신 모범 답안 비교 + 자기 점검
- [ ] **멀티턴 모드 (P1)**: 내 대답 후 상대가 미리 준비된 후속 질문 1~2개를 이어서 던짐 (주제별 후속 질문 데이터)

### F2. 인출 카드 (즉시 인출) — P0

- [ ] 앞면: 한국어 문장 + 능력 태그. 예: `[문장 잇기] "어제 친구를 만나서 영화를 봤어요"`
- [ ] 출력 방식 3가지, 카드마다 또는 설정에서 선택:
  - **타이핑**: 제한 시간(기본 15초, 짧은 문장 10초) 안에 입력 → 가나 기준 자동 채점 (정답/거의 정답/오답, 다른 부분 색 표시)
  - **블록 조립**: 섞인 단어 블록을 탭해 순서대로 배열 (모바일·손 하나로 빠르게)
  - **속으로 말하기**: 머릿속으로 말한 뒤 정답 보기 → 자기평가
- [ ] 정답 공개 시 TTS 자동 재생 + 가나·후리가나·뜻·뉘앙스 한 줄
- [ ] 정답/자기평가 결과 → Leitner 5단계(당일→1→2→4→8일) 갱신, 오답은 세션 끝 재출제
- [ ] 대체 정답 허용: 한 카드에 정답 여러 개 등록 가능 (예: `見ました` / `観ました`)
- [ ] 단축키(PC): `Enter` 제출, `Tab` 정답 보기, `1/2/3` 자기평가, `R` 다시 듣기

### F3. 이어 쓰기 드릴 (문장 잇기·답 늘리기) — P0

- [ ] 시작 문장 1개 제시. 예: `日曜日に友達に会いました。`
- [ ] 접속 표현 칩 선택(`それで` / `〜から` / `でも` / `例えば`) → 이어지는 문장 타이핑 (30초 제한) → 예시 문장 공개
- [ ] 3단계까지 이어 완성본을 TTS로 듣기
- [ ] **답변 확장 공식 모드**: `답 → 이유 → 예시 → 되묻기` 4칸 순서대로 채우기
- [ ] Day마다 최소 3세트

### F4. 금지어 챌린지 (막혔을 때 버티기) — P1

- [ ] 설명할 대상 + 사용 금지 단어 제시. 예: "`スマホ` 를 쓰지 말고 스마트폰을 설명하세요"
- [ ] 1분 동안 `〜みたいなもの` `〜するときに使う` 등 바꿔 말하기 표현으로 설명 타이핑
- [ ] 금지어를 입력하면 즉시 빨간 표시
- [ ] 모범 설명 예시 공개

### F5. 듣기 → 반응 대화문 — P0(Week 1분), P1(나머지)

- [ ] 대화문 4~10턴, 이어폰 재생. 자막 3단계 (`일+한` → `일본어만` → `없음`)
- [ ] **마지막 턴은 나에게 던지는 질문** → 들은 즉시 타이핑으로 대답 (20초 제한)
- [ ] 이해 퀴즈 2~3문항 (4지선다)
- [ ] **받아쓰기 모드**: 한 턴을 듣고 가나로 받아쓰기 → 자동 채점 (듣기 정확도 훈련)
- [ ] 맞장구·되묻기 표현 색 강조
- [ ] 턴 길게 누르기 → 인출 카드로 추가

### F6. TTS 플레이어 — P0

- [ ] Web Speech API `ja-JP`, 속도 0.7× / 0.85× / 1.0× / 1.2× (기본 0.85×, Week 3부터 1.0×)
- [ ] 반복 1/3/5회 + 간격 1~3초 (무성 쉐도잉용)
- [ ] 일본어 음성 없으면 설치 안내 배너 — **갤럭시 탭 기준 안내 문구**:
  `설정 > 일반 > 텍스트 음성 변환(TTS) > 기본 엔진을 "Google 음성 인식 및 합성"으로 선택 > 엔진 설정 > 음성 데이터 설치 > 日本語 다운로드` (삼성 TTS 엔진에 일본어가 있으면 그대로 사용 가능)
- [ ] 안드로이드 크롬은 음성 목록을 늦게 불러오므로 `voiceschanged` 이벤트 이후 `ja-JP` 음성을 다시 찾는다 (처음에 "음성 없음"으로 오판하지 않음)
- [ ] 설정에 "음성 테스트" 버튼: `こんにちは、よろしくお願いします` 재생으로 설치 여부 즉시 확인
- [ ] 재생 중 문장 하이라이트, 대화문은 화자별 음성/피치
- [ ] **소리 끄기 모드**: 이어폰도 못 쓰는 상황용. 모든 TTS 자동재생 중단, 텍스트만으로 진행 가능 (단, 듣기 단계는 "나중에 하기"로 보류됨)

## 6. 화면 & 반응형 기준

### 6.1 화면 목록

### 6.2 태블릿 우선 설계 (주 사용 기기)

모든 화면은 **태블릿 가로 모드를 기준으로 먼저 설계**하고, 휴대폰·PC로 확장한다. 개발 중 실기기 테스트도 태블릿이 1순위.

**기본 출력 방식 (태블릿)**
- 프리토킹 채팅·이어 쓰기·금지어 챌린지: **타이핑** (화면 키보드가 넓어 로마자 입력이 빠름. 외장 키보드 연결 시 PC 단축키 그대로 동작)
- 인출 카드 복습: **블록 조립** 기본, 타이핑으로 전환 가능 (복습은 속도가 중요하므로 탭이 더 빠름)

**태블릿 레이아웃 기준**
- [ ] **가로 모드**: 화면 좌 60% 채팅/카드, 우 40% 힌트·생존 표현집 패널 상시 표시. 화면 키보드가 올라오면 우측 패널은 접히고 채팅 영역 + 입력창 + 남은 시간만 남는다
- [ ] **세로 모드**: 1단 레이아웃, 힌트·표현집은 하단 시트. 블록 조립 영역은 화면 하단 절반 (양손 엄지로 닿는 위치)
- [ ] 화면 키보드가 열린 상태에서도 **질문 말풍선, 입력창, 제출 버튼, 남은 시간**이 한 화면에 모두 보인다 (가로 모드 포함)
- [ ] 블록 조립의 블록은 최소 **48×48px**, 블록 간격 8px 이상 (손가락 오입력 방지)
- [ ] 외장 키보드 감지 시 단축키 안내 표시 (`Enter` 제출, `Tab` 정답 보기 등)
- [ ] 분할 화면(Split View / 멀티윈도우)으로 폭이 좁아져도 휴대폰 레이아웃으로 자연스럽게 전환
- [ ] **레이아웃 판정은 폭 + 입력 방식 조합**: 태블릿 가로 모드는 폭이 1024px를 넘는 경우가 많으므로, `pointer: coarse`(터치)이면 폭이 넓어도 PC용 사이드바 대신 태블릿 레이아웃을 쓴다
- [ ] 이어폰 연결/해제 시 재생 중인 TTS가 멈추면 "다시 듣기" 버튼이 바로 보인다
- [ ] 블루투스 이어폰(갤럭시 버즈 등)의 재생 지연을 고려해, 반응 타이머는 **TTS 재생이 끝난 시점부터** 시작한다
- [ ] **삼성 DeX 모드 / 북커버 키보드** 사용 시: 마우스·키보드 입력이 감지되면 PC 레이아웃과 단축키로 자동 전환
- [ ] 기준 해상도: 갤럭시 탭 S 시리즈 가로 약 1280×800, 세로 약 800×1280 (CSS px), 보급형 탭 A 시리즈 포함해 깨짐 없음

### 6.3 기기별 레이아웃 요약

| 기기 | 폭 | 레이아웃 |
|---|---|---|
| 휴대폰 | 360–767px | 하단 탭바, 채팅은 메신저형 전체 화면, 입력창은 키보드 바로 위 고정, 블록 조립 기본 추천 |
| **태블릿 (주 기기)** | 768px+ 이면서 터치 | 6.2 기준. 하단 탭바(가로 모드에선 좌측 아이콘 레일) |
| PC | 1024px+ 이면서 마우스 | 좌측 사이드바, 콘텐츠 최대 960px, 타이핑 기본 추천, 키보드 단축키 |

### 6.4 측정 가능한 UX 기준

- [ ] 어느 화면에서든 "프리토킹 시작"까지 **탭 2번 이내**
- [ ] 프리토킹 중 생존 표현 삽입 **탭 2번 이내** (시트 열기 → 표현 탭)
- [ ] 로마자 입력 → 가나 변환 지연 체감 없음 (**50ms 이내**)
- [ ] 모바일 키보드가 올라와도 입력창·제출 버튼·남은 시간이 모두 보임
- [ ] 터치 대상 **44×44px 이상**, 일본어 본문 모바일 **20px 이상**
- [ ] 360px 폭에서 가로 스크롤 없음, 첫 로딩 3G 기준 **3초 이내**
- [ ] 모든 학습 단계가 **마이크 없이** 완료 가능

## 7. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Vite + React + TypeScript | 빠른 개발, 정적 빌드 |
| 스타일 | Tailwind 또는 CSS Modules | 반응형 |
| 일본어 입력 | `wanakana` (로마자↔가나) | 키보드 설치 없이 입력, 채점용 정규화 |
| 채점 | 가나 정규화 + 문자 단위 diff | 한자/가나 혼용, 부호 차이 무시 |
| 음성 출력 | Web Speech API `speechSynthesis` | 무료 |
| 녹음 (선택 기능) | `MediaRecorder` + IndexedDB | 서버 불필요 |
| 데이터 / 진도 | 정적 JSON / `localStorage` + 내보내기 | 서버·로그인 없음 |
| 배포 | GitHub Pages / Vercel 무료 | 비용 0원 |

### 기술 리스크

| 리스크 | 대응 |
|---|---|
| 한자로 입력한 답의 가나 변환 불가 (브라우저에 형태소 분석기 없음) | 정답 데이터에 한자 표기와 가나 표기 둘 다 보관 → 입력이 둘 중 어느 쪽과도 맞으면 정답. 한자 일부만 섞이면 "거의 정답"으로 표시하고 자기평가로 확정 |
| 자유 대답(프리토킹)은 문법 자동 채점 불가 | 의도적으로 채점하지 않음. 리포트는 양·속도·접속 표현·되묻기 등 측정 가능한 것만 |
| 모바일 키보드가 화면을 가림 | `visualViewport` API로 입력창 위치 보정, **태블릿 실기기(가로·세로 모두) 테스트를 P0 완료 조건에 포함**, 휴대폰은 그다음 |
| 기기별 TTS 음성 차이 | 음성 선택, 설치 안내 |
| 안드로이드 크롬의 TTS가 긴 문장에서 중간에 끊기는 현상 | 문장 단위로 쪼개서 순차 재생 |
| 삼성 키보드 자동 수정·조합 입력이 로마자 변환과 충돌 | F0의 입력 속성 지정 + compositionend 처리, 삼성 키보드·Gboard 실기기 테스트를 P0 완료 조건에 포함 |
| 크롬과 삼성 인터넷의 동작 차이 | 크롬 1순위로 개발·검수, 삼성 인터넷은 주요 흐름(Day 1 완료)만 확인 |
| 타이핑이 실제 말하기 감각을 대체하지 못함 | 1.2의 한계 명시, 무성 쉐도잉 + 선택형 음성 체크인(F9) |
